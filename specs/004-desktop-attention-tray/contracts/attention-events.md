# Contract: Attention Events and Effects

## Scope

This contract defines the runner-main boundary between validated Phase 2 observations/window lifecycle events and Phase 3 desktop effects. It is profile-local and not exposed to website renderer code.

## Input Events

### `observation`

Payload is the existing `XPathObservationState`. Before dispatch, main MUST verify:

- sender is the runner window main frame;
- sender origin equals the configured profile origin;
- payload is an object with exact supported mode;
- booleans, count, text, change flag and timestamp have valid primitive/range types;
- payload mode equals active profile mode.

Invalid input is ignored or logged with deduplication and creates no desktop effect.

### `focus`

Generated from the runner window focus event. Carries no renderer payload.

### `clear`

Generated by tray “Xóa cảnh báo” or the validated runner control command. Repeated clear is idempotent.

### `quit`

Generated once by the shared runner quit path. This is terminal for the controller.

## Effect Contract

| Effect | Trigger | Clear condition |
| --- | --- | --- |
| Window attention | New eligible background change when enabled | Focus, clear, empty/zero, disable or quit. |
| Badge | Every meaningful count/attention update when enabled | Zero/empty, focus, clear, disable or quit. |
| Tray unread state | Every attention transition | Focus, clear, empty/zero or quit. |
| Native popup | Eligible background event after cooldown and final condition check | Closed/cancelled on focus, clear, empty/zero or quit. |

## Popup Coalescing

1. If no popup was accepted in the preceding 2000 ms, an eligible event may show immediately.
2. Otherwise, replace `pendingPopup` with the latest valid observation and keep one timer for the remaining interval.
3. On timer expiry, use the latest valid state and show only if attention remains active, the window is unfocused, popup preference remains enabled, and popup support is available.
4. Focus, clear, empty/zero and quit cancel both pending data and timer.

## Mode Presentation

- `badge_count`: badge/tooltip use the current numeric count.
- `existence`: active state is a boolean indicator; tooltip says “Có thông báo mới”.
- `text_content`: active state is a boolean indicator; popup may use the safe text preview, while tooltip says “Có thông báo mới”.

No mode claims that attention means the website marked content unread/read.
